### get_absolute_url()

Метод возвращает URL конкретного объекта. Полезен при использовании DetailView или при создании ссылки в шаблонах. Рекомендуется использовать в связке с CBV (классами представлений), в таком случае Django сам будет находить путь к объекту.

```Python
class Person(models.Model):
  ...

  def get_absolute_url(self):
    return f"/person/{self.pk}/"
```

Более надежный способ - через reverse()

```Python
from django.urls import reverse

class Person(models.Model):
  ...

  def get_absolute_url(self):
    return reverse('person-detail', kwargs={'pk': self.pk})  # path('person/<int:pk>/', views.person, name='person-detail')
```

### clean()

Кастомная валидация объекта. Метод clean() позволяет реализовать собственные правила валидации на уровне модели. Это особенно полезно, когда нужно проверить взаимосвязь нескольких полей или применить логику, которую нельзя описать в параметрах самих полей. clean() вызывается вручную, но автоматически запускается внутри full_clean() и в админке при сохранении объектов

```Python
class Event(models.Model):
  title = models.CharField(max_length=100)
  start_date = models.DateField()
  end_date = models.DateField()

  def clean(self):
    # Проверка: дата окончания не раньше даты начала
    if self.end_date < self.start_date:
      raise ValidationError('Дата окончания не может быть раньше даты начала')
```

### full_clean()

Проверка всех полей модели. Запускает валидацию всех полей модели, вызывает метод clean (при наличии), поднимает исключение ValidationError (при ошибке). Для валидации данных перед сохранением через формы или админку лучше использовать full_clean() - он запускает все встроенные и кастомные проверки.

```Python
person = Person(first_name='', last_name='Smith')
person.full_clean()  # Выбросит ValidationError, если first_name пустой
```

### save()

Переопределения сохранения. Вызывается при сохранении объекта в БД. Используют для переопределения поведения ДО/ПОСЛЕ сохранения

```Python
class Article(models.Model):
  title = models.CharField(max_length=200)
  slug = models.SlugField(unique=True, blank=True)

  def save(self, *args, **kwargs):
    if not self.slug:
      self.slug = slugify(self.title)
    super().save(*args, **kwargs)  # важно вызывать super().save(), иначе объект не сохранится
```

### delete()

Переопределение поведения удаления: добавление дополнительный действий, например, логирование, удаление файлов и т.д.

```Python
class File(models.Model):
  name = models.CharField(max_length=100)
  file = models.FileField(upload_to='uploads/')

  def delete(self, *args, **kwargs):
    self.file.delete(save=False)  # удаляем физический файл
    super().delete(*args, **kwargs)
```


Django - высокоуровневый веб-фреймворк на языке Python, предназначенный для быстрого создания надёжных и масштабируемых веб-приложений. Он помогает разработчикам создавать сайты и веб-сервисы без необходимости писать всё с нуля.

Фреймворк - набор инструментов и библиотек, помогающих решать типичные задачи при создании веб-приложений:

* Обработка запросов и маршрутизация URL
* Работа с базой данных
* Создание HTML-шаблонов
* Формы и валидация данных
* Аутентификация пользователей
* Панель администратора

Преимущества:

* Скорость разработки
* Безопасность - встроенная защита от SQL-инъекций, XSS, CSRF и т.д.
* Масштабируемость - используется в крупных проектах с миллионами пользователей
* Админ-панель - автоматическое создание интерфейса управления данными
* Гибкость - поддержка API, кастомных моделей, приложений и т.д.

Подходит для: лендингов, сайтов-визиток, CRM, CMS, блогов, новостных порталов, внутренних панелей, интернет-магазинов, REST API для мобильных приложений, интерфейсы для Data Science / аналитики.

Архитектура Django – MTV:

* Model - описание данных и логики БД
* Template - отвечает за HTML-шаблоны и отображение
* View - содержит логику обработки запросов

Возможности:

* Создание веб-сайтов с динамическим контентом
* Работа с БД через ORM (без SQL)
* Генерация HTML-страниц через шаблоны
* Создание REST API через DRF
* Обработка форм и загрузка файлов
* Регистрация пользователей и аутентификация
* Управление проектом через админку

Файлы

* `manage.py` - главный управляющий скрипт. Используется для запуска сервера, миграций и других команд. Входная точка. Командная утилити для управления Django-проектом. Обёртывает `django-admin` и передаёт ему настройки проекта. Помогает запускать сервер, создавать/применять миграции, создавать суперпользователя, открывтть Django shell. Знает, где лежат настройки (settings.py) и подключает их при каждом запуске. Используется для управления проектом через команды.
* `settings.py` - файл с настройками проекта (БД, приложения, локализация)
* `urls.py` - маршруты проекта: какие адреса обрабатываются какими функциями
* `asgi.py` и `wsgi.py` - файлы для запуска сервера в разных режимах (production/development)

Django ORM позволяет работать с базой без написания SQL

Админка - удобный интерфейс для управления данными

Представление (View) - это функция или класс в Django, принимающая HTTP-запрос и возвращающая HTTP-ответ. Это "мозг" обработки запросов. Функция получает объект запроса (request) и возвращает объект HttpResponse.

ModelForm - специальный класс Django, который автоматически создаёт HTML-форму на основе модели. Он упрощает работу: избавляет от необходимости ручного создания каждого поля формы.

## **Модели**

Модель – Python-класс, описывающий стуктуру таблицы в БД. Django использует ORM (Object-Relational Mapping), чтобы автоматически Python-код в SQL-команды. Moдель наследуется от django.db.models.Model, который описыватет структуру данных, хранящихся в БД вашего приложения. Каждая модель представляет собой таблицу в БД, а атрибуты модели соответствуют столбцам этой таблицы. Модели определяют поля, типы данных, ограничения и связи с другими моделями.

В моделе поле определяет атрибут объекта модели и столбец в соответствующей таблице базы. Поле описывает один из параметров, характеризующих сущность, которую представляет модель. Основные характеристики поля: тип данных, имя, параметры. Аспекты полей:

* тип столбца
* веб-компонент (вид ввода) - поле порождает веб-компонент (текстареа и тд) при использовании в админ-панели или при создании форм, Django генерирует его автоматически
* требования к валидации (clean_<field_name>)

Мета-классы позволяют задать дополнительные настройки для модели (принцип сортировки записей, нейминг таблиц, отображение в админке)

```Python
    class Meta:
        # Кастомизация названия таблицы в базе
        db_table = 'custom_table_name'
    
        # Указать приложение, к которому относится модель
        app_label = 'users'
    
        # Параметр получения последней записи (для .latest() и .earliest())
        get_latest_by = 'created_at'
    
        # Ограничение (на добавление людей с одинаковым именем и фамилией)
        constraints = [
            models.UniqueConstraint(
                fields=['first_name', 'last_name'],
                name='unique_full_name'
            ),
        ]  # аналог unique_together, который не используется после 4.2 версии Django
    
        # Ускорение выборки по определённм полям
        indexes = [
            models.Index(fields=['last_name']),
        ]
    
        # Дополнительные права для объектов модели
        permissions = [
            ("can_moderate", "Может модерировать записи"),
        ]
    
        # Абстрактная модель не создаёт свою таблицу в БД, но может быть унаследована другими моделями
        # (можно вынести create_at и updated_at в базовую абстрактную модель)
        abstract = True
    
        # Не создаёт новую таблицу, использует таблицу-родителя.
        # Необходимо для изменения поведения модели (сортировка или добавление методов без мутирования оригинала)
        proxy = True
```

Пример с Proxy

```Python
class PersonProxy(Person):
  class Meta:
    proxy = True
    ordering = ['last_name']
```
